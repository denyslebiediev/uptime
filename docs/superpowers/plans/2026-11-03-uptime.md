# Power-cut tracker ("uptime") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track power cuts at two apartments with Raspberry Pi heartbeats, a Cloudflare Worker + D1 API, a public bilingual GitHub Pages dashboard and an iOS Scriptable widget.

**Architecture:** Each Pi POSTs `{boot_id, uptime}` every 30 s to a Worker that keeps one D1 table of "spans" (runs of heartbeats per boot) and derives power cuts, connection drops, reboots and switch-offs on read with one pure function. The no-build static site and the widget only read the public `GET /status` and `GET /events` endpoints; all calendar maths happens in the browser in Europe/Kyiv time.

**Tech Stack:** Cloudflare Workers (TypeScript, Wrangler 4, D1, Rate Limiting binding), Vitest 4 + `@cloudflare/vitest-plugin`; bash + curl + systemd on Raspberry Pi OS (bookworm/trixie); plain HTML/CSS/ES modules tested with `node --test`; Scriptable (iOS); GitHub Actions + GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-02-power-tracker-design.md` (approved mockups in `docs/superpowers/specs/mockups/`). Read the spec section named in each task before starting it.

## Global Constraints

- All stored and served timestamps are **unix seconds of Worker receive time**. Nothing from the Pi's wall clock is ever stored; any timestamp field in a heartbeat body is ignored.
- Constants (spec §5): heartbeat every **30 s**; `GAP = 120`; write cap **10 s**; reboot window **600 s**; stale after **86 400 s**; stale-packet tolerance **30 s**.
- Heartbeat body ≤ **512 bytes**; `boot`/`pb` match `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/`; `up`/`pu` finite with `0 ≤ x ≤ 3.2e8`; `ev ∈ {reboot, poweroff}`; `pc ∈ {none, reboot, poweroff}`.
- Calendar maths only in **Europe/Kyiv** (fall back to `Europe/Kiev` if the runtime rejects it) via `Intl`; never hard-code +2/+3. Days can be 23 h, 24 h or 25 h. Weeks are ISO (Monday 00:00).
- Device ids `centralna`, `rayduzhna`; names `Центральна 50`/`Centralna 50`, `Райдужна 71`/`Rayduzhna 71`; short names `Центральна`/`Centralna`, `Райдужна`/`Rayduzhna`.
- API base **`https://uptime-api.denyslebiediev.com`**; site **`https://denyslebiediev.com/uptime/`** — every site asset path is relative (`./…`).
- Every GET response, errors included, carries `Access-Control-Allow-Origin: *`. `/status`: `Cache-Control: public, max-age=15`; `/events`: `Cache-Control: public, max-age=60`; `OPTIONS` → `204` with `Access-Control-Allow-Methods: GET, OPTIONS`, `Access-Control-Max-Age: 86400`. `POST /hb` sends no CORS headers. Public GETs rate-limited to **120 requests / 60 s per IP**.
- Worker: Wrangler 4, `wrangler.jsonc`, `compatibility_date: "2026-11-03"`, observability on, D1 database `uptime` created with `--location eeur`, read replication off. Production D1 commands always pass `--remote` (Wrangler 4 defaults to local).
- Tests: Worker uses `vitest@^4.1` + `@cloudflare/vitest-plugin` (not the deprecated `@cloudflare/vitest-pool-workers`); site uses `node --test` with no dependencies; Pi scripts use a plain bash test harness plus `shellcheck`.
- Site: no build step, no npm dependencies, no chart library, native ES modules. Text from the API is inserted with `textContent`, never `innerHTML`. Every `localStorage` access is wrapped in try/catch. Storage keys: `uptime.theme` (`auto|light|dark`), `uptime.lang` (`uk|en`).
- State is never shown by color alone: always an icon plus a word. Live `no_signal` wording: **"No signal" / "Немає зв'язку"** plus **"probably a power cut" / "ймовірно, немає світла"** where there is room.
- Design tokens, sections and copy follow spec §8 and `mockups/site.html`; widget follows spec §9 and `mockups/widget.html`.
- Pi: bash + curl + systemd only; curl flags `-fsS --connect-timeout 5 --max-time 10`, `-H 'Content-Type: application/json' --data …` (never `--json`, never `--retry`, never `-k`).
- Secrets are never committed: `.dev.vars`, `*.env`, `/etc/uptime-hb/auth` contents, tunnel hostnames/tokens/e-mails (docs use placeholders like `<ssh-hostname>`).
- Git: imperative one-line commit messages exactly as written in each task, **no `Co-Authored-By` lines**. Pushing to GitHub, creating the GitHub repo, `wrangler deploy`, and anything touching Cloudflare or a Pi are owner-confirmed steps — stop and ask before them.

## Review Focus

1. **API unreachable, 5xx or malformed JSON** → the site keeps the last good data and shows "Can't reach the server — data as of HH:MM"; the widget renders its cache with "offline · as of HH:MM". Tests: Task 10 (site `loadWithFallback`), Task 14 checklist.
2. **A device with no heartbeats yet** (just configured) → `/status` and `/events` return it with `state: "unknown"`, `since: null`, `seen: null`, `first_seen: null`; site and widget show "Waiting for the first signal" / "Очікуємо перший сигнал" and do not crash. Tests: Task 2 (`live([])`), Task 4 (`/status` with an empty table), Task 9 (`periodStats` with `first_seen: null`).
3. **Periods before monitoring started or only partly observed** → the Summary shows "No data" for a period with zero observed time instead of "100 % with power"; partly observed periods compute % over observed time only. Tests: Task 9.
4. **Viewer not in Kyiv time** (owner abroad, laptop set to UTC, iOS lacking `Europe/Kyiv`) → every time and every day boundary is still Kyiv time. Tests: Task 8 runs the time/format suite under `TZ=UTC` and `TZ=America/New_York`.
5. **Long or ongoing cut across midnight / several days** → off-time is split across every day it touches, the ongoing cut counts up to `now`, "longest cut" uses `now − start` marked ongoing, and the timeline draws a segment on each day. Tests: Task 9 (stats), Task 11 (timeline renderer on a 50-hour cut).

## Shared contract (all tasks code against this; Task 1 puts the TypeScript in `worker/src/model.ts`)

```ts
export type Shutdown = 'none' | 'reboot' | 'poweroff'
export type Kind = 'power_off' | 'no_connection' | 'reboot' | 'device_off' | 'no_signal'
export type Flag = 'provisional' | 'connecting' | 'after_shutdown' | 'stale'
export type LiveState = 'on' | 'no_signal' | 'rebooting' | 'device_off' | 'unknown'
export interface Span { id: number; device: string; boot_id: string; boot_at: number; first_seen: number; last_seen: number; alive_until: number | null; shutdown: Shutdown }
export interface Interval { device: string; kind: Kind; start: number; end: number | null; flags: Flag[] }
export interface Live { state: LiveState; since: number | null; seen: number | null; flags: Flag[] }
export interface Heartbeat { boot: string; up: number; ev?: 'reboot' | 'poweroff'; pb?: string; pu?: number; pc?: Shutdown }
export interface Device { id: string; name: { uk: string; en: string }; short: { uk: string; en: string } }
export interface StatusDevice extends Device, Live { today: [number, number | null, Kind][] }   // intervals clipped to [day.start, day.end]
export interface StatusBody { now: number; day: { start: number; end: number }; devices: StatusDevice[] }
export interface EventsDevice extends Device, Live { first_seen: number | null }
export interface EventsBody { now: number; from: number; to: number; devices: EventsDevice[]; iv: [string, Kind, number, number | null, Flag[]][] } // iv rows: [device, kind, start, end, flags], unclipped, sorted by start
export const GAP = 120, WRITE_CAP = 10, REBOOT_WINDOW = 600, STALE_AFTER = 86_400, STALE_TOLERANCE = 30, MAX_BODY = 512, UP_MAX = 3.2e8
export const EVENTS_DEFAULT_DAYS = 35, EVENTS_MAX_DAYS = 400
```

HTTP:
- `POST /hb` — `Authorization: Bearer <token>`, JSON `Heartbeat` → `204` | `400 {"error":"bad_body"}` | `401` | `409 {"error":"stale"}` | `413`.
- `GET /status` → `StatusBody`.
- `GET /events?from=<unix>&to=<unix>` → `EventsBody`; defaults `to = now`, `from = to − 35 d`; `to − from > 400 d` or non-integers → `400 {"error":"bad_range"}`.
- `GET` over the limit → `429`. Unknown path → `404 {"error":"not_found"}`.

Pi ↔ files: `/etc/uptime-hb/env` (`UPTIME_HB_URL=https://uptime-api.denyslebiediev.com/hb`), `/etc/uptime-hb/auth` (`Authorization: Bearer <token>`, mode 0600), `/var/lib/uptime-hb/state` (one line `<boot_id> <uptime> <none|reboot|poweroff>`). Test overrides: `UPTIME_HB_ETC`, `UPTIME_HB_STATE_DIR`, `UPTIME_HB_PROC`, `UPTIME_HB_INTERVAL`.

### Task 2: Pure derivation (`derive`, `live`)

Spec: §5.4 (every branch is a named test below), §5.3 rule 7.

**Files:**
- Create: `worker/src/derive.ts`
- Test: `worker/test/derive.test.ts`

**Interfaces:**
- Consumes: `Span`, `Interval`, `Live`, `Kind`, `Flag`, `GAP`, `REBOOT_WINDOW`, `STALE_AFTER` from `src/model.ts`.
- Produces:
  - `derive(spans: Span[], now: number): Interval[]` — `spans` are ONE device's, ascending by `id`; intervals come back in start order with `device` copied from the spans; `[]` for `[]`. Ends with at most one open interval (`end: null`) from the live state, starting at `L.last_seen`: `no_signal` (flags `['provisional']`, plus `'stale'`), `reboot` while rebooting, `device_off` after a poweroff marker. `on` and `unknown` add nothing.
  - `live(spans: Span[], now: number): Live` — reads only the last span; `flags` is `['stale']` or `[]`.
